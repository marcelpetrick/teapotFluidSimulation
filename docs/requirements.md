# Vision requirements traceability

This matrix maps the original vision to the current implementation and its evidence.
Critical regression contracts are mapped to named tests and assertion text in
[requirement-assertions.json](requirement-assertions.json). The pipeline checks those references
and executes their test files. This is a targeted safety net, not complete semantic coverage.

Read the status and qualification together. A linked test file identifies evidence; it does not prove physical accuracy.

The matrix contains **151 requirements** across all 18 vision sections.

## How to maintain this matrix

1. Find the requirement before changing behaviour.
2. Update its implementation and verification links.
3. Run the named tests or measurement.
4. Update the status only when the evidence supports it.
5. If the vision changes, review its affected requirements before updating the vision fingerprint.

Do not use code-coverage percentages as requirement coverage. The original brief contains historical unchecked tasks; this matrix records current status.

Run `node scripts/check-requirements.mjs` after editing this matrix.
The pipeline checks IDs, counts, evidence links, the vision fingerprint and all numbered vision sections.
It does not establish physical validation.

## Acceptance gates that remain open

- Represented-volume drift exceeds one percent in recorded pouring cases. Interior density cannot establish that gate.
- No measured real-pot validation exists. Two 3D resolutions do not establish a converged physical model.
- Real-phone speed and full accessibility compliance have not been established.
- Isolated return-phase analysis and complete snapshot-buffer reuse remain incomplete.

These gaps restrict claims. They are not silently counted as completed work. See [questions](../questions.md) for owner-dependent work.
